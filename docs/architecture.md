# 架构与已知限制

MCP 客户端通过 stdio 与 `server.py` 通信。入口将参数传给 `WorkflowDriver`，并把预期拒绝转成结构化错误。离线文件检查走 `file_inspection.py`，原生操作经 `Driver` 和 `WindowsBackend` 核对目标后执行。

| 层 | 模块 | 职责 |
|---|---|---|
| 协议 | `server.py`、`errors.py` | 工具定义、输入 schema、统一错误格式 |
| 控制 | `driver.py`、`workflow.py` | 识别目标，检查运行状态，编排多步动作和读回 |
| Windows | `win32_backend.py`、`simulator_launcher.py` | 读取进程与窗口信息，调用标准 Windows 窗口消息，打开正常登录器 |
| 遥测 | `constants.py`、`memory.py`、`file_state.py`、`read_setup.py` | 固定构建识别与只读遥测解码 |
| UI 操作 | `preparation.py`、`initialization.py`、`view_extensions.py` | 已识别对话框、控制器和画面的操作及证据 |
| 验收 | `completion_monitor.py`、`file_inspection.py` | 运行事件关联、NC 检查、保存网格摘要及可选验收脚本 |

## 支持范围

- 目标为 FANUC0iMF 7.2.5.2 的一个已知构建。服务通过路径、哈希、进程创建时间、基址和窗口归属核对身份。其他版本要重新确认控件和内存布局。
- 标准窗口工具与本机登录器用于交互式桌面。完成监视器通过可选 Frida 依赖观察目标进程。启用前请先阅读工具说明。
- 待现场验收的流程包括真实回参考点、冷启动登录和新监视器完整切削链。自动化用例使用合成控件、测试文件与替身，覆盖协议和状态处理。
- 报警详情通过 MSG 页面和截图查看。刀具设置支持已识别的映射与字段，新刀具类型对话框要逐一验证。

## 使用时应核对的状态

- 写操作在每个服务进程内串行执行。多个 MCP 会话可以各自启动一个服务，请为同一仿真器只保留一个执行写操作的会话。
- 在打开、另存与续跑期间，保持 NC 编辑状态、文件路径和准备参数稳定。打开前保存要保留的编辑，提交后主动读回结果。
- 暂停记录基于进程、程序位置、坐标和计数。若暂停后修改了程序或设置，应重新从确认过的初始状态执行。
- 完成监视器的证据对应其观察到的 worker 和文档。换程序后重新建立监视，使用 `completed` 时同时核对运行目标。
- 监视器的就绪等待从 Frida 脚本加载完成后开始。挂接和清理期间，其他控制动作需要等待。
- 文件检查以字面 NC 内容和已保存的版本 2 网格为依据。槽深、轮廓、公差和切削过程需要对应程序与独立的验证依据。
